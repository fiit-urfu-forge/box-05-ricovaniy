# Спецификация: LLM Wiki — десктопное приложение на C# / Avalonia

---

## [01] СУЩНОСТИ И ОПЕРАЦИИ

### Сущности

**Vault**
- `Path: string` — абсолютный путь к корневой папке vault
- `Name: string` — имя папки (отображаемое)
- Выбирается один раз при первом запуске, сохраняется в настройках приложения
- После Delete (очистка vault через приложение) и Update (смена vault-папки) автоматически запускается полная переиндексация wiki

**RawFile** (файл в `raw/`)
- `RelativePath: string` — путь относительно vault
- `FileName: string`
- `Extension: string` — md, txt, pdf, png, jpg, jpeg, gif, webp и др.
- `AddedAt: DateTime`
- `SizeBytes: long`
- `Type: enum { Text, Pdf, Image, Other }`

**WikiPage** (файл в `wiki/`)
- `RelativePath: string`
- `Title: string` — первый H1 из markdown
- `Content: string` — полный текст .md файла
- `Links: List<string>` — все `[[wikilinks]]`, извлечённые из контента
- `LastModified: DateTime`

**GraphNode**
- `Id: string` — RelativePath файла
- `Label: string` — имя файла без расширения
- `Type: enum { RawFile, WikiPage, IndexPage }`

**GraphEdge**
- `Source: string` — Id ноды-источника
- `Target: string` — Id ноды-цели
- `Weight: int` — количество упоминаний (для будущей визуализации)

**ChatMessage**
- `Role: enum { User, Assistant }`
- `Content: string`
- `Timestamp: DateTime`

**AppSettings**
- `VaultPath: string`
- `ClaudeCredentialsPath: string` — путь до `.claude/.credentials`
- `ApiKey: string` — если введён вручную
- `WikiOnlyMode: bool` — галочка "только из вики"
- `GitRemoteUrl: string?` — URL удалённого GitHub репозитория (null если синхронизация не настроена)
- `GitAutoSync: bool` — включён ли автосинк
- `GitAutoSyncIntervalMinutes: int` — интервал автосинка (по умолчанию 15 минут)

**GitSyncStatus** (in-memory, не персистируется)
- `State: enum { NotConfigured, Idle, Pushing, Pulling, Conflict, Error }`
- `LastSyncAt: DateTime?`
- `ConflictingFiles: List<ConflictEntry>?`

**ConflictEntry**
- `RelativePath: string` — путь к конфликтующему файлу
- `LocalContent: string` — локальная версия
- `RemoteContent: string` — версия из GitHub
- `LocalCommitTime: DateTime`
- `RemoteCommitTime: DateTime`

---

### Структура vault на диске

```
vault/
├── raw/           # оригинальные файлы, не изменяются агентом
├── wiki/          # md-страницы, создаёт и обновляет Claude
├── index.md       # карта базы знаний
├── log.md         # журнал изменений
└── CLAUDE.md      # схема/инструкции для агента (ingest/query/lint)
```

### Операции

**Vault**
- Create: выбор папки через диалог (первый запуск) → автоматически создаётся структура (`raw/`, `wiki/`, `CLAUDE.md`, `index.md`, `log.md`) → запускается начальная индексация
- Read: открытие существующего vault при запуске приложения
- Update: смена vault-папки через "Открыть другой vault" → после выбора новой папки автоматически запускается полная переиндексация
- Delete: очистка vault через приложение (удаление содержимого `wiki/`, `index.md`, `log.md`, при этом `raw/` сохраняется) → после очистки автоматически запускается полная переиндексация с нуля

**RawFile**
- Create: drag & drop в интерфейс ИЛИ кнопка "Добавить файл" → file picker → файл копируется в `raw/` → автоматически запускается операция **Ingest**
- Read: просмотр содержимого файла во встроенном вьювере
- Delete: только через файловый менеджер ОС (приложение не предоставляет Delete)
- Update (реиндексация): кнопка "Переиндексировать vault" запускает полный Ingest по всем файлам `raw/`

**WikiPage**
- Create/Update: создаётся и обновляется **только агентом Claude** в ходе Ingest
- Read: просмотр .md файла во встроенном вьювере с рендерингом Markdown
- Delete: только вручную через ОС

**Граф связей**
- Read: визуализация нод и рёбер, парсинг `[[wikilinks]]` из wiki/*.md
- Построение: автоматически после каждого Ingest + кнопка "Обновить граф"
- Навигация: клик по ноде → открывает файл во вьювере

**Чат**
- Create: отправка вопроса → Claude Code отвечает
- Read: отображение истории текущего сеанса
- Delete: очищается автоматически при перезапуске приложения
- Режимы: WikiOnly (галочка выключена) — Claude читает только wiki; Extended (галочка включена) — Claude может использовать свои знания

**Операции Claude Code (агентные)**
- **Ingest**: при добавлении нового файла в `raw/` — Claude читает файл, создаёт/обновляет wiki-страницы, расставляет `[[wikilinks]]`, обновляет `index.md` и `log.md`
- **Query**: ответ на вопрос пользователя по базе знаний
- **Lint**: проверка базы на битые ссылки, устаревшие страницы, противоречия (запускается вручную по кнопке)

**GitSync**
- Setup: пользователь вводит URL репозитория + Personal Access Token (PAT) в настройках → приложение инициализирует `git init` в папке vault (если нет `.git`) и добавляет remote → если remote пустой — первый Push; если remote уже содержит данные — первый Pull с последующей переиндексацией
- Push (ручной): кнопка "Синхронизировать" → `git add -A` + `git commit -m "sync: <timestamp>"` + `git push`
- Pull (ручной): кнопка "Получить изменения" → `git pull`; если конфликты — переходим в режим ConflictResolve
- AutoSync: фоновый таймер (интервал из настроек) → Pull → если нет конфликтов → Push; если конфликты → прерывается и показывает уведомление
- ConflictResolve: пользователь видит список конфликтующих файлов с двумя панелями (локальная vs. удалённая версия) → для каждого файла выбирает "Оставить моё" или "Взять из GitHub" → после всех выборов применяются изменения + `git add -A` + `git commit` + `git push`
- Disable: в настройках убрать remote (`git remote remove origin`); `.git` остаётся на диске, синхронизация отключается

## [02] ГРАНИЦЫ ЗНАЧЕНИЙ

**Пустой vault**
- Если `raw/` и `wiki/` пусты — показывать пустое состояние с подсказкой "Добавьте первый файл"
- `index.md` и `log.md` создаются при первом Ingest, если их нет
- `CLAUDE.md` — создаётся приложением автоматически при выборе vault (если не существует), содержит базовую схему инструкций для агента

**Граф при пустой wiki**
- Отображается пустой холст с текстом "Нет связей — добавьте файлы и запустите индексацию"

**Чат без файлов в базе**
- В режиме WikiOnly с пустой wiki: Claude предупреждает, что база пуста, и предлагает добавить файлы
- В режиме Extended: Claude отвечает из собственных знаний без ограничений

**Размер файлов**
- Максимальный размер одного файла для Ingest: **50 MB** — при превышении показывать предупреждение "Файл слишком большой для обработки"
- Изображения: Claude Code передаёт их агенту как есть; очень большие изображения (>20 MB) могут вызвать timeout — см. секцию [03]

**Длинные имена файлов**
- Файлы с именами длиннее 255 символов — отклонять при добавлении с ошибкой

**Количество файлов в vault**
- Нет жёсткого ограничения; при > 500 файлов в `raw/` предупреждать, что операция Ingest займёт значительное время

**GitHub синхронизация — граничные случаи**
- Синхронизация не настроена → все Git-кнопки скрыты, в настройках показывается секция "Подключить GitHub"
- PAT истёк или невалиден → ошибка при Push/Pull с подсказкой обновить токен в настройках
- Репозиторий приватный — допустимо; публичный — предупреждение "Репозиторий публичный, ваши данные будут видны всем. Продолжить?"
- Файлы > 100 MB в vault → `git push` упадёт (ограничение GitHub); предупреждать заранее при Setup и при добавлении таких файлов
- AutoSync во время активного Ingest → отложить Pull/Push до завершения Ingest

## [03] ОБРАБОТКА ОШИБОК И СБОЕВ

**Claude Code не установлен**
- При запуске приложения проверяется наличие `claude` в PATH
- Если не найден → модальное окно с инструкцией по установке + кнопка "Установить" (запускает команду установки через `Process.Start`) + кнопка "Проверить снова"
- Пока Claude Code не установлен — приложение не запускается дальше

**Пользователь не авторизован в Claude Code**
- Проверяется наличие `.claude/.credentials`
- Если не найден → открывается встроенная консоль (терминал-виджет) с запуском `claude login` интерактивно, пользователь видит процесс авторизации в реальном времени
- После успешного `claude login` приложение продолжает запуск

**Credentials введены вручную**
- Если автоматическое чтение `.credentials` не удалось → показывается поле для ввода API key вручную
- Ключ проверяется тестовым запросом; если невалиден — показывается ошибка "Недействительный API key"

**Ошибка во время Ingest**
- Если Claude Code вернул ошибку в процессе обработки файла → показывать inline-уведомление "Ошибка при индексации [filename]: [описание]"
- Остальные файлы в очереди продолжают обрабатываться
- Неудачный файл помечается иконкой в панели файлов с возможностью повторить

**Timeout агента**
- Если Claude Code не отвечает более **5 минут** → показывать кнопку "Отменить операцию" + уведомление "Операция заняла слишком много времени"
- Прерывание через `CancellationToken`

**Файловая система**
- Если vault-папка недоступна при запуске (удалена, диск отключён) → модальное окно "Vault не найден по пути [path]. Выбрать другой vault?"
- Если файл удалён через ОС снаружи → приложение узнаёт об этом только при ручной переиндексации; до этого момента файл может отображаться в дереве как существующий

**Невалидные типы файлов**
- При drag & drop файла неподдерживаемого типа → показывать tooltip "Поддерживаются: текстовые файлы, PDF, изображения"
- Файл не копируется в `raw/`

**Повреждённый PDF или изображение**
- Claude Code не сможет прочитать файл → ошибка Ingest для этого файла, остальные продолжают обрабатываться

**Конфликт имён файлов**
- Если в `raw/` уже есть файл с таким именем → диалог "Файл уже существует. Заменить / Переименовать / Отмена"

**Git: ошибки сети и авторизации**
- Нет интернета при Push/Pull → toast-ошибка "Нет соединения с GitHub. Изменения сохранены локально"
- Неверный PAT → "Ошибка авторизации GitHub. Обновите токен в настройках"
- Remote недоступен (репо удалено) → "Репозиторий недоступен. Проверьте URL в настройках"
- AutoSync при отсутствии сети → тихо пропускает итерацию, индикатор синхронизации показывает дату последнего успешного синка

**Git: конфликты при Pull**
- Если `git pull` обнаруживает конфликты → приложение прерывает Pull, восстанавливает рабочее состояние (`git merge --abort`) и открывает экран разрешения конфликтов
- AutoSync при конфликте → прерывается, показывает красный индикатор с текстом "Требуется разрешение конфликтов" + кнопка перехода к экрану конфликтов; следующие итерации AutoSync не запускаются до разрешения

## [04] ОБРАТНАЯ СВЯЗЬ И СОСТОЯНИЯ

**Состояние "пусто"**
- Файловое дерево пусто → "Vault пуст. Добавьте первый файл"
- Граф пуст → "Нет связей. Добавьте файлы и запустите индексацию"
- Чат без сообщений → "Задайте вопрос по вашей базе знаний"

**Состояние "в процессе"**
- Ingest: прогресс-бар или спиннер с текстом "Claude обрабатывает [filename]..." + вывод агента в реальном времени (стриминг через SDK)
- Query (чат): анимированный индикатор набора текста ("Claude печатает...") + ответ стримится по мере генерации
- Lint: спиннер "Проверка базы знаний..."
- Переиндексация: прогресс вида "Обработано 12 / 47 файлов"
- Git Push/Pull: индикатор синхронизации в статус-баре "↑ Синхронизация..." / "↓ Получение изменений..."

**Состояние "ошибка"**
- Inline-уведомление (не модальное) красного цвета с описанием ошибки и кнопкой "Повторить" где применимо
- Критические ошибки (нет Claude Code, нет vault) — модальные окна
- Git-конфликт при AutoSync — красный индикатор в статус-баре с кнопкой "Разрешить конфликты"

**Состояние "успех"**
- После Ingest: "✓ [filename] добавлен и проиндексирован" — toast-уведомление на 3 секунды
- После Lint: показывается краткий отчёт ("Найдено 3 битые ссылки, 1 страница без связей")
- После переиндексации: "✓ Vault переиндексирован. Обработано N файлов"
- После Push: "✓ Синхронизировано с GitHub" + дата/время в статус-баре
- После Pull (без конфликтов): "✓ Изменения получены" + если появились новые файлы — автоматически запускается переиндексация
- После разрешения конфликтов: "✓ Конфликты разрешены, vault синхронизирован"

**Блокировка повторного действия**
- Во время Ingest кнопка "Добавить файл" остаётся доступной (файлы ставятся в очередь)
- Во время Query кнопка отправки сообщения блокируется до получения ответа
- Кнопка "Переиндексировать" блокируется на время выполнения Ingest/переиндексации
- Кнопки Push/Pull блокируются во время активной Git-операции
- AutoSync не запускается если есть неразрешённые конфликты

**Стриминг ответа агента**
- Вывод Claude Code в чате отображается потоково (токен за токеном), не ждёт полного ответа

**Экран разрешения конфликтов**
- Список конфликтующих файлов с именем и путём
- Для каждого файла — две панели: "Моя версия (локальная)" и "Версия из GitHub" с датой каждой
- Кнопки "Оставить мою" / "Взять из GitHub" для каждого файла
- Кнопка "Применить все решения" активна только когда все конфликты разрешены

## [05] ПЕРСИСТЕНТНОСТЬ И СОСТОЯНИЕ

**Где хранятся данные**
- Пользовательские файлы: в vault-папке на диске (выбирается пользователем)
- Граф связей: не хранится отдельно — парсится из `[[wikilinks]]` в `wiki/*.md` при каждом открытии vault
- Настройки приложения (`VaultPath`, `ApiKey`, `WikiOnlyMode` и др.): в стандартном месте ОС (`%APPDATA%/LLMWiki/settings.json` на Windows, `~/.config/LLMWiki/settings.json` на Linux/Mac)
- История чата: только в памяти текущего сеанса, не сохраняется

**При перезапуске**
- Приложение читает `settings.json`, восстанавливает путь к vault
- Граф перестраивается из файлов на диске
- История чата очищается
- Файловое дерево строится из реального состояния vault

**При потере vault-папки**
- При старте → модальное окно с предложением выбрать другой vault
- Настройки приложения сохраняются

**При обновлении схемы settings.json**
- Новые поля имеют значения по умолчанию; старые `settings.json` без новых полей загружаются без ошибок (десериализация с defaults)

**CLAUDE.md**
- Создаётся автоматически при первом открытии vault (если отсутствует)
- Содержит базовые инструкции для агента: правила ingest, query, lint, форматирование wiki-страниц, как расставлять `[[wikilinks]]`
- Пользователь может редактировать его вручную для кастомизации поведения агента

**GitHub синхронизация — персистентность**
- `GitRemoteUrl`, `GitAutoSync`, `GitAutoSyncIntervalMinutes` хранятся в `settings.json` (не в vault)
- PAT (Personal Access Token) хранится в системном keystore ОС (`Windows Credential Manager` / `libsecret` на Linux / `Keychain` на Mac) — **не в `settings.json` и не в vault**, чтобы токен не попал в репозиторий
- `.git/` папка живёт внутри vault-папки на диске — синхронизируется между устройствами как часть репозитория
- `.gitignore` создаётся автоматически в корне vault при Setup; исключает `settings.json` (настройки локальные) и системные файлы ОС (`.DS_Store`, `Thumbs.db`)
- При перезапуске: `GitSyncStatus` сбрасывается в `Idle` (или `NotConfigured`); AutoSync таймер перезапускается если был включён
- При смене vault: Git-настройки предыдущего vault не переносятся; для нового vault нужно настраивать синхронизацию заново

**Библиотека claude-agent-sdk-dotnet**
- Исходный код копируется в репозиторий проекта (не NuGet), чтобы можно было дорабатывать при необходимости

## [06] КРИТЕРИИ ГОТОВНОСТИ

### Обязательные сценарии (должны работать без ошибок)

1. **Первый запуск**: нет Claude Code → показывается модалка установки → после установки показывается `claude login` в консоли → после авторизации пользователь выбирает vault-папку → приложение открывается
2. **Добавление файла**: пользователь drag & drop PDF в интерфейс → файл копируется в `raw/` → автоматически запускается Ingest → Claude Code создаёт wiki-страницу → граф обновляется → toast "✓ Файл проиндексирован"
3. **Чат в режиме WikiOnly**: пользователь задаёт вопрос → Claude отвечает только по содержимому wiki, ссылается на конкретные страницы → ответ стримится
4. **Чат в режиме Extended**: галочка включена → Claude может использовать свои знания помимо wiki
5. **Граф связей**: открывается вкладка "Граф" → отображаются ноды файлов и рёбра из `[[wikilinks]]` → клик по ноде → открывается файл во вьювере
6. **Файловое дерево**: показывает реальную структуру папок vault → клик по файлу → открывается во вьювере (PDF, изображение, markdown)
7. **Переиндексация**: пользователь вручную удалил файл из `raw/` через ОС → нажимает "Переиндексировать" → граф и дерево обновляются
8. **GitHub Setup**: пользователь вводит URL репозитория и PAT → приложение инициализирует git, создаёт `.gitignore` → первый Push → на втором устройстве пользователь клонирует через Pull → vault появляется с переиндексацией
9. **Разрешение конфликтов**: на двух устройствах изменён один wiki-файл → при Pull появляется экран конфликтов → пользователь выбирает версию для каждого файла → изменения применяются и пушатся

### Граничные случаи, которые должны обрабатываться корректно

- Drag & drop файла неподдерживаемого типа → предупреждение, файл не добавляется
- Файл с таким же именем уже существует в `raw/` → диалог замены/переименования
- Vault-папка недоступна при запуске → предложение выбрать другую
- Файл > 50 MB → предупреждение, Ingest не запускается
- Claude Code завис → timeout 5 минут, кнопка "Отменить"
- Пустой vault → пустые состояния с подсказками везде, а не крэш

### Что НЕ надо делать

- Не добавлять векторную базу данных или embedding-поиск (используем LLM-навигацию по `index.md` и `[[wikilinks]]`)
- Не добавлять авторизацию пользователей / мультиаккаунтность
- Не добавлять облачную синхронизацию (только локальный vault)
- Не добавлять редактор wiki-страниц в интерфейсе (wiki редактирует только агент)
- Не менять стек без согласования

## [07] АНАЛИЗ SDK — ЧТО ЕСТЬ И ЧТО НУЖНО ДОРАБОТАТЬ

### Что есть в `claude-agent-sdk-dotnet` (gunpal5) из коробки

| Возможность | Статус |
|---|---|
| `ClaudeAgent.QueryAsync(prompt, options)` — одиночный запрос | ✅ |
| `ClaudeSdkClient` — многоходовые разговоры (multi-turn) | ✅ |
| Стриминг ответов (`IAsyncEnumerable<Message>`) | ✅ |
| Инструменты агента: Read, Write, Edit, Bash | ✅ |
| `ClaudeAgentOptions.Cwd` — рабочая директория (vault path) | ✅ |
| `ClaudeAgentOptions.SystemPrompt` — системный промпт | ✅ |
| `ClaudeAgentOptions.AllowedTools` / `DisallowedTools` | ✅ |
| `ClaudeAgentOptions.PermissionMode` (Default / AllowAll / Deny) | ✅ |
| `CancellationToken` — отмена операции | ✅ |
| `CliNotFoundException` — обнаружение отсутствия Claude Code | ✅ |
| Чтение `CLAUDE.md` из рабочей директории | ✅ (через `Cwd`) |
| Отслеживание токенов и стоимости (`ResultMessage.Usage`) | ✅ |

### Что отсутствует и нужно доработать в SDK (или обойти на уровне приложения)

**1. Интерактивный терминал для `claude login`**

SDK не поддерживает интерактивный ввод — он общается с Claude Code через stdin/stdout в неинтерактивном режиме. Для `claude login` нужен полноценный PTY (pseudo-terminal) с поддержкой интерактивного ввода.

_Решение:_ реализовать отдельный `TerminalWidget` в приложении, который запускает `claude login` напрямую через `Process` с перенаправлением stdin/stdout/stderr, минуя SDK. SDK использовать только для агентных операций после авторизации.

**2. Чтение `.claude/.credentials` для проверки авторизации**

SDK не предоставляет API для проверки статуса авторизации — только выбрасывает исключение при попытке выполнить запрос без credentials.

_Решение:_ приложение самостоятельно проверяет наличие файла `.claude/.credentials` перед инициализацией SDK. Путь к `.claude/` определять из `%USERPROFILE%` (Windows) / `$HOME` (Linux/Mac).

**3. Отсутствие прогресса по файлам во время Ingest**

SDK стримит текстовые блоки (`TextBlock`, `ToolUseBlock`) но не предоставляет структурированных событий о прогрессе обработки файлов.

_Решение:_ парсить `ToolUseBlock` сообщения в реальном времени (когда агент вызывает `Read`, `Write` и т.д.) и отображать пользователю какой файл сейчас обрабатывается.

**4. Ограничение `MaxTurns` (по умолчанию 25)**

При большом vault с множеством файлов агент может исчерпать лимит ходов во время Ingest/Lint.

_Решение:_ для операций Ingest и Lint устанавливать `MaxTurns = 200` (или более) в `ClaudeAgentOptions`. Документировать это в спеке явно.

**5. Нет встроенной очереди задач**

Если пользователь добавляет несколько файлов подряд, SDK не управляет очередью — каждый `QueryAsync` запускает независимый процесс.

_Решение:_ реализовать `IngestQueue` на уровне приложения — `Channel<FileInfo>` с одним consumer-воркером, который последовательно вызывает SDK для каждого файла.

### Итого: что нужно написать поверх SDK

1. `TerminalWidget` (Avalonia) — PTY-терминал для `claude login`
2. `CredentialsChecker` — проверка наличия `.claude/.credentials`
3. `IngestQueue` — очередь файлов для последовательной обработки
4. `AgentProgressParser` — парсинг `ToolUseBlock` для отображения прогресса
5. `WikiLinkParser` — парсинг `[[wikilinks]]` из `.md` файлов для построения графа (SDK не предоставляет)
6. `GitSyncService` — обёртка над `git` CLI (`Process`) для операций init, add, commit, push, pull, статус конфликтов; хранение PAT в системном keystore; AutoSync таймер

## [08] ДЕТАЛЬНЫЕ ПРАВИЛА

### Файлы и типы

**Поддерживаемые типы — whitelist расширений:**
- Text: `.md`, `.txt`, `.csv`, `.json`, `.xml`, `.yaml`, `.yml`, `.html`
- Pdf: `.pdf`
- Image: `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`
- Всё остальное → `Type.Other`; при drag & drop показывать tooltip "Неподдерживаемый тип файла", файл не добавляется

**Drag & drop папки:**
- Рекурсивно сканировать, добавлять все файлы с поддерживаемыми расширениями
- Unsupported файлы внутри папки — пропускать молча, итоговое уведомление: "Добавлено N файлов, пропущено M неподдерживаемых"
- Вложенная структура папок сохраняется внутри `raw/`

**Symlinks и hardlinks:**
- Игнорировать при индексации и drag & drop — не копировать, не обходить

**Case-insensitive конфликт имён (`File.pdf` vs `file.pdf`):**
- На любой ОС считать конфликтом → показывать диалог "Файл с похожим именем уже существует. Заменить / Переименовать / Отмена"

**Unicode, emoji, RTL в именах файлов:**
- Поддерживаются полностью; все пути через `Path.Combine`, нормализация через `NFC`

### Vault — инициализация и доступ

**Проверка доступа на запись:**
- При выборе vault-папки — немедленно проверять запись тестовым файлом `.llmwiki_write_check`, затем удалять его
- Vault на read-only носителе → блокировать с ошибкой "Нет прав на запись в выбранную папку"

**Непустая папка как vault:**
- Разрешать; создавать только отсутствующие элементы структуры (`raw/`, `wiki/`, `CLAUDE.md`, `index.md`, `log.md`)
- Существующие файлы не трогать

**Частично повреждённые системные файлы:**
- `CLAUDE.md` отсутствует или пуст → пересоздать с дефолтным содержимым
- `index.md` / `log.md` отсутствуют → пересоздать пустыми с заголовком
- `raw/` или `wiki/` отсутствуют → пересоздать папки

**`raw/` или `wiki/` удалены во время работы приложения:**
- Обнаруживается при следующей операции (Ingest/переиндексация) → папки пересоздаются автоматически

**Vault внутри другого vault:**
- Показывать предупреждение "Выбранная папка находится внутри другого vault. Продолжить?" — разрешать после подтверждения

### Ingest — детальные правила

**Режимы Ingest:**
- **Инкрементальный** (по умолчанию): сравнивать `LastWriteTime` + `SizeBytes` файла с кешированными значениями в `raw/.ingest_state.json`; обрабатывать только новые/изменённые
- **Полный** (ручная кнопка "Переиндексировать полностью"): обрабатывать все файлы в `raw/`, игнорируя кеш

**`raw/.ingest_state.json`** — внутренний файл приложения, не редактируется пользователем:
```json
{
  "files": {
    "article.pdf": { "lastWriteTimeUtc": "...", "sizeBytes": 12345, "ingestedAt": "..." }
  }
}
```

**Файл изменился во время Ingest:**
- Ingest для этого файла уже запущен → завершить с текущей версией, при следующей инкрементальной проверке файл будет переиндексирован снова

**Отмена через CancellationToken:**
- Отменяет только текущий файл в очереди
- Частично созданные wiki-файлы текущего файла — удалять (rollback)
- Остальные файлы в очереди очищаются (не обрабатываются)
- `ingest_state.json` не обновляется для отменённого файла

**"Переиндексировать" во время активного Ingest:**
- Дождаться завершения текущего файла → отменить остаток очереди → запустить полную переиндексацию

**Успешность Ingest:**
- Считается успешным если Claude записал хотя бы один `.md` файл в `wiki/` без исключения от SDK
- Обновить запись в `ingest_state.json` только при успехе

**Разрешённые tools Claude по режимам:**

| Tool | Ingest | Query | Lint |
|---|---|---|---|
| Read | ✅ | ✅ | ✅ |
| Write | ✅ (только `wiki/`) | ❌ | ✅ (только `wiki/`) |
| Edit | ✅ (только `wiki/`) | ❌ | ✅ (только `wiki/`) |
| Bash | ❌ | ❌ | ❌ |

**Защита `raw/` от записи агентом:**
- `DisallowedTools` не запрещает запись в конкретную папку — защита реализуется через явный запрет в `CLAUDE.md`: "Never write to the `raw/` directory"
- Если Claude всё равно создал файл вне `wiki/` — удалять автоматически после завершения операции, логировать инцидент

**Один raw-файл → несколько wiki-страниц:**
- Claude сам решает сколько страниц создать — не ограничивать
- Сопоставление raw → wiki страниц ведётся через метаданные в frontmatter каждой wiki-страницы:
```yaml
---
source: raw/article.pdf
generated_at: 2026-01-01T12:00:00Z
---
```

**Wiki-страницы при удалении raw-файла:**
- При переиндексации (ручной или после Pull) — обнаруживать wiki-страницы, чей `source` в frontmatter указывает на несуществующий raw-файл
- Помечать их через добавление в frontmatter: `orphaned: true`
- В графе отображать такие ноды другим цветом ("orphan node")
- Lint сообщает об orphan-страницах в отчёте
- Автоматически НЕ удалять — только помечать

**Orphan wiki-страницы без frontmatter `source`:**
- Страницы, созданные вручную пользователем или агентом без метаданных — не считать orphan, обрабатывать как обычные wiki-страницы

### Wikilinks и граф — детальные правила

**Парсинг форматов:**
- `[[PageName]]` → ссылка на страницу с именем `PageName`
- `[[PageName|Alias]]` → ссылка на `PageName`, отображать как `Alias`
- `[[folder/page]]` → поддерживать относительные пути от `wiki/`
- Ссылки case-insensitive при разрешении

**Битые ссылки:**
- Wikilink указывает на несуществующую страницу → "ghost node" в графе (другой цвет/пунктирный контур)
- Клик по ghost node → сообщение "Страница не найдена"

**Self-links:** игнорировать, не добавлять в граф

**Циклические ссылки:** допустимы, граф их корректно отображает

**Дублирующиеся wikilinks в одном файле:** `Weight` считается один раз (уникальные рёбра)

**`index.md` и `log.md`:** отображаются в графе как `GraphNode.Type = IndexPage`

**`WikiPage.Title`:**
- Берётся первый `# H1` в файле
- Если H1 отсутствует → использовать имя файла без расширения
- Если H1 несколько → брать первый

**Граф при большом количестве нод:**
- При > 200 нод показывать предупреждение о возможном замедлении
- Виртуализация рендера — реализовать по возможности через viewport culling

**Layout:** force-directed алгоритм (стандарт для wiki-графов)

**Позиция нод:** не сохраняется между сессиями, пересчитывается при каждом открытии

**Идентификация нод при переименовании файла:**
- Id ноды = `RelativePath` → при переименовании файла через ОС id меняется
- Старые wikilinks становятся битыми — пользователь исправляет вручную или через Lint

### Viewer — детальные правила

**Поддерживаемые форматы во viewer:**
- Markdown (`.md`) → рендеринг через Markdig
- PDF → встроенный PDF viewer (например, через PdfiumViewer или аналог для Avalonia)
- Изображения (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`) → нативный ImageControl Avalonia
- Text (`.txt`, `.csv` и др.) → показывать как plain text с моноширинным шрифтом
- `Type.Other` → показывать иконку файла + кнопку "Открыть в системном приложении" (`Process.Start`)

**Markdown диалект:** CommonMark + GFM (GitHub Flavored Markdown) через Markdig

**HTML внутри Markdown:** sanitize — вырезать `<script>`, `<iframe>`, `<object>`, `on*` атрибуты; остальной HTML допускать

**Кодировки текста:** UTF-8 как основная; при ошибке чтения — попытка автодетекта (UTF-16, Windows-1252, CP1251); при невозможности определить → показывать "Не удалось определить кодировку файла"

**Бинарные/нечитаемые файлы:** показывать "Не удалось отобразить содержимое файла"

**Файл изменился на диске пока открыт во viewer:**
- Показывать баннер "Файл изменился. Обновить?" с кнопкой → перечитать при подтверждении

**Файл заблокирован другим процессом:**
- Показывать ошибку "Файл используется другим приложением"

**Файл удалён через ОС пока открыт во viewer:**
- Показывать баннер "Файл был удалён"

**Максимальный размер для viewer:**
- Markdown/текст > 10 MB → показывать первые 10 MB с предупреждением "Файл обрезан для отображения"
- PDF — без ограничений (PDF viewer работает с файлом на диске)

### Чат — детальные правила

**WikiOnly режим (галочка выключена):**
- `SystemPrompt` включает: "Answer only based on the wiki files in the vault. Do not use your own knowledge."
- Claude получает доступ `Read` только к `wiki/`, `index.md`, `log.md`

**Extended режим (галочка включена):**
- `SystemPrompt` позволяет использовать собственные знания
- Claude получает доступ `Read` ко всему vault

**Контекстное окно при большом wiki:**
- Claude сам навигирует по `index.md` и `[[wikilinks]]` — не передавать весь vault сразу
- `Cwd` = путь к vault, агент читает файлы по необходимости

**Conversational context в сеансе:**
- Поддерживается через `ClaudeSdkClient` (multi-turn); весь диалог сеанса передаётся агенту

**Пустое сообщение:** кнопка Send заблокирована

**Несколько Query подряд:** ставить в очередь, не параллельно

**Query и Ingest одновременно:** разрешить — Claude читает текущее состояние wiki на момент запроса

**Lint:**
- Запускается вручную
- Проверяет: битые wikilinks, orphan-страницы, страницы без связей (isolated nodes), дублирующийся контент
- Возвращает структурированный отчёт, отображаемый в отдельной панели
- Lint может обновлять wiki-страницы (исправлять битые ссылки) — только с явного разрешения пользователя после показа предпросмотра изменений
- Lint и AutoSync: если Lint изменяет файлы → изменения попадут в следующий AutoSync Push автоматически

### Авторизация и секреты

**Приоритет источников авторизации:** `.claude/.credentials` (автоматически) → ApiKey из keystore (введённый вручную)

**Хранение ApiKey:** системный keystore ОС (как PAT для Git), не `settings.json`

**`.credentials` просрочен или битый:** определяется при первом запросе к SDK (исключение) → переходить к флоу `claude login`

**`settings.json` повреждён:** сбросить до defaults, показать уведомление "Настройки сброшены до значений по умолчанию"

**Несколько экземпляров приложения:** запрещать второй запуск — показывать "LLM Wiki уже запущен" и завершаться

### Git — детальные правила

**Требования:** `git` должен быть установлен и доступен в PATH; при отсутствии — показывать ошибку при попытке настроить синхронизацию, не при старте приложения

**PAT аутентификация через git CLI:**
- Передавать через URL: `https://<pat>@github.com/user/repo.git`
- PAT читается из системного keystore при каждой git-операции, не хранится в URL постоянно

**`.git` уже существует с другим remote:**
- При Setup показывать: "Репозиторий уже подключён к [current_remote]. Заменить на [new_remote]? Да / Нет"

**`.gitignore` содержимое (создаётся при Setup):**
```
# LLM Wiki app settings (local only)
settings.json

# OS files
.DS_Store
Thumbs.db
desktop.ini

# Ingest state cache
raw/.ingest_state.json
```

**`.gitattributes` (создаётся при Setup):**
```
* text=auto eol=lf
*.pdf binary
*.png binary
*.jpg binary
*.jpeg binary
*.gif binary
*.webp binary
```

**Default branch:** `main`

**Remote branch не существует при первом Push:** использовать `git push -u origin main`

**Diverged history / rebase:** не поддерживать rebase — показывать ошибку "История разошлась. Разрешите конфликты вручную или сбросьте синхронизацию в настройках"

**Force-push в remote:** обнаруживается как diverged history — см. выше

**Merge conflicts вне wiki-файлов** (например, `CLAUDE.md`, `index.md`):
- Обрабатывать аналогично wiki-файлам: показывать в экране конфликтов с выбором версии

**Извлечение `RemoteContent` при конфликте:**
- До `git merge --abort` сохранять `MERGE_HEAD` версию через `git show MERGE_HEAD:<path>` для каждого конфликтующего файла

**Файлы > 100 MB:**
- При Setup и при добавлении файла в vault — предупреждать: "Файл [name] превышает 100 MB. GitHub не принимает такие файлы. Добавить в `.gitignore`?"
- Git LFS — не поддерживать в v1

**`git commit` без изменений:** `git status --porcelain` вернёт пустой вывод → пропускать commit и push тихо

**AutoSync во время ручного Push/Pull:** откладывать следующую итерацию; текущая операция не прерывается

**AutoSync выключается во время операции:** дождаться завершения текущей git-операции, затем остановить таймер

**Коммит после Ingest:** не создавать автоматически — только при ручном Push или AutoSync

**Pull после которого появились новые файлы в vault:** автоматически запустить инкрементальную переиндексацию

---

### Общие технические правила

**DateTime:** все хранятся в UTC (`DateTime.UtcNow`); отображать в локальном времени пользователя (`TimeZoneInfo.Local`)

**Пути:** везде использовать `Path.Combine`; в git-контексте заменять `\` на `/`

**Line endings:** LF во всех vault-файлах (контролируется через `.gitattributes`)

**Логирование:**
- Хранилище: `%APPDATA%/LLMWiki/logs/` (Windows), `~/.local/share/LLMWiki/logs/` (Linux), `~/Library/Logs/LLMWiki/` (Mac)
- Ротация: файл за каждый день, хранить 7 дней
- Уровни: Info, Warning, Error; чувствительные данные (PAT, ApiKey) — не логировать никогда

**Rate limit Claude API:** показывать ошибку с таймером "Повторить через N секунд" (парсить из заголовка `Retry-After`)

**Retry сетевых ошибок:** 3 попытки с exponential backoff (1s → 2s → 4s) для Claude API и Git операций

**Offline режим:** Query и Ingest недоступны (кнопки заблокированы с tooltip "Нет подключения"); граф, файловое дерево и viewer работают

**Telemetry:** не собирать никаких данных

**Обновление приложения:** не реализовывать в v1; пользователь обновляет вручную

**Поддерживаемые ОС в v1:** Windows 10/11 (приоритет); Linux и macOS — через Avalonia, но без официального тестирования и гарантий

**Производительность:** нет требований к памяти/CPU, кроме разумного (не более 500 MB RAM в покое)

## [09] АРХИТЕКТУРНЫЕ РЕШЕНИЯ

### Источник истины и консистентность

- **Источник истины** — `wiki/*.md` на диске. `ingest_state.json` — только кеш оптимизации, не источник истины
- При краше посередине Ingest: при следующем старте сканировать `wiki/` на файлы с невалидным или отсутствующим frontmatter — удалять такие файлы (считать частично записанными)
- Принадлежность wiki-страницы к raw-файлу — только через поле `source` в frontmatter. Если Claude удалил/изменил frontmatter — страница становится orphan без `source`, обрабатывается как созданная вручную. Несколько страниц с одинаковым `source` — обе валидны

### Повторный Ingest того же raw-файла

- Claude обновляет существующие wiki-страницы поверх через `Edit`
- Ручные правки пользователя в `wiki/` — **перезаписываются агентом**. Это осознанное решение: `wiki/` — зона агента, `raw/` — зона пользователя

### State machine операций (гонки)

```
Idle → Ingesting → Idle
Idle → Linting   → Idle
Idle → Syncing   → Idle
Idle → Querying  (параллельно с Idle и Ingesting)
```

**Правила совместимости:**

| | Ingest | Lint | Sync | Query |
|---|---|---|---|---|
| **Ingest** | ❌ очередь | ❌ ждёт | ❌ откладывает | ✅ |
| **Lint** | ❌ ждёт | ❌ | ❌ откладывает | ❌ ждёт |
| **Sync** | ❌ откладывает | ❌ откладывает | ❌ | ✅ |
| **Query** | ✅ | ❌ ждёт | ✅ | очередь |

- Pull с новыми файлами → инкрементальная переиндексация запускается **после** завершения Pull
- AutoSync откладывается если идёт Ingest или Lint; ждёт завершения Query перед Push

### Граница ответственности: приложение vs агент

| Ответственность | Кто |
|---|---|
| Консистентность wikilinks | Агент (Claude) |
| Orphan detection | Приложение (парсинг frontmatter) |
| Валидация frontmatter | Приложение (при чтении) |
| Удаление файлов вне `wiki/` | Приложение (post-operation cleanup) |
| Path traversal защита | Приложение (сканирование после каждой агентной операции) |
| Запрет записи в `raw/` | Логически через `CLAUDE.md` + cleanup приложением |

**Path traversal (Claude создаёт `../`):** после каждой агентной операции сканировать vault на файлы вне `raw/`, `wiki/`, корневых `index.md`, `log.md`, `CLAUDE.md` — удалять автоматически, логировать как security incident.

**Claude создаёт > 50 новых wiki-файлов за один Ingest:** показывать предупреждение пользователю после завершения.

**MaxTurns:** Ingest = 200, Lint = 100, Query = 50.

### Уникальный идентификатор WikiPage

- `RelativePath` от корня vault в нижнем регистре (для case-insensitive сравнения)
- H1 — только для отображения (`Title`), не идентификатор
- При переименовании файла через ОС → id меняется, старые wikilinks становятся битыми, Lint обнаруживает

### UX галочки режима чата

- **Галочка выключена** = **WikiOnly** (режим по умолчанию): Claude читает только `wiki/`
- **Галочка включена** = **Wiki + AI**: Claude может использовать собственные знания
- Label рядом с галочкой: `"Wiki + AI"` (чтобы было понятно что включается при активации)

### Прозрачность ответов в WikiOnly режиме

- Рядом с каждым ответом Claude в чате показывать badge **"из wiki"** (иконка + текст)
- Смысл: пользователь понимает что ответ основан на содержимом его wiki-файлов
- Badge не гарантирует отсутствие галлюцинаций — Claude сам ссылается на конкретные wiki-страницы в тексте ответа, пользователь может проверить

### Видимость процесса Ingest

**Во время Ingest** — раздвижная панель "Активность агента" показывает:
- Лог в реальном времени: стриминг `TextBlock` и названия вызываемых tools из `ToolUseBlock` ("📖 Читает: article.pdf", "✏️ Создаёт: wiki/concept.md", "🔗 Обновляет: index.md")

**После завершения Ingest** — итоговый отчёт:
- Создано wiki-страниц: N
- Обновлено wiki-страниц: N
- Новых связей: N
- Время обработки: Xs

### Threading model (C# / Avalonia)

- **UI поток** — только Avalonia dispatcher, никаких blocking calls
- **Ingest/Git/Claude SDK** — `async/await` на `ThreadPool` через `Task.Run`
- **IngestQueue** — `Channel<FileInfo>` (bounded, capacity 100) с одним consumer-воркером
- **Стриминг Claude** — `IAsyncEnumerable` читается в background task, UI обновляется через `Dispatcher.UIThread.InvokeAsync`
- **Cancellation** — `CancellationTokenSource` на каждую операцию, linked с app-level токеном
- **Нет `lock` на UI-данных** — только `ObservableCollection` через dispatcher

### `ClaudeSdkClient` lifecycle

- **Ingest, Lint** — новый instance на каждую операцию, `await DisposeAsync()` после завершения
- **Query (чат)** — один `ClaudeSdkClient` на весь сеанс (multi-turn), пересоздаётся при перезапуске
- Длинный чат-контекст не сбрасывается в рамках сеанса — это фича (continuity)

### `GitSyncService` state machine

```
NotConfigured → Idle (после Setup)
Idle → Pulling → Pushing → Idle
Idle → Pulling → ConflictDetected → (ConflictResolved → Pushing → Idle)
Pushing/Pulling → Error → Idle
```

- Rollback при конфликте: `git merge --abort`
- Retry: 3 попытки с exponential backoff (1s → 2s → 4s) для сетевых ошибок
- `git status --porcelain` перед commit — если пусто, пропускать Push тихо

### FileSystemWatcher

- **Не использовать** для основной логики (event storms на Windows, ненадёжность на сетевых дисках)
- Сканирование диска — только при ручной переиндексации и после Pull
- **Исключение:** `FileSystemWatcher` только для баннера "Файл изменился" во viewer

### Единица транзакции Ingest

- Один raw-файл = одна транзакция
- Rollback = удаление всех wiki-файлов с `source: <этот файл>`, созданных в текущей операции
- Отслеживание созданных файлов — через хук на `ToolUseBlock` с именем `Write`/`Edit` в стриме SDK

### PTY / интерактивный терминал

- Использовать библиотеку **`Pty.Net`** (Microsoft, MIT) — кроссплатформенно абстрагирует ConPTY (Windows) и forkpty (Linux/macOS)
- При отмене `claude login` пользователем — kill процесса через `Pty.Net` + dispose

### Однопользовательский lock

- При старте создавать `%APPDATA%/LLMWiki/app.lock` с PID процесса
- При старте: если файл существует → проверить живой ли процесс с этим PID → живой: "LLM Wiki уже запущен", exit → мёртвый: удалить lock, продолжить
- При штатном завершении — удалять lock
- При завершении приложения: app-level `CancellationToken` отменяет фоновые задачи; git-операция дожидается завершения (timeout 30 секунд)

### Незавершённый merge после краша

- При старте: `git status --porcelain` — если `UU` (unmerged) файлы → автоматически открывать экран разрешения конфликтов

### Битые служебные файлы при старте

| Файл | Действие |
|---|---|
| `settings.json` повреждён | Сбросить до defaults, показать уведомление |
| `ingest_state.json` повреждён | Удалить, пересоздать пустым; следующий Ingest обработает все файлы как новые |
| `.git` повреждён | Показать ошибку при git-операции + кнопку "Сбросить git-синхронизацию" |
| `app.lock` с мёртвым PID | Удалить автоматически, продолжить запуск |

### Масштабируемость

- **Граф > 200 нод**: предупреждение о возможном замедлении; viewport culling при рендере
- **500+ файлов drag & drop**: все в `IngestQueue` (bounded channel); прогресс "В очереди: N"
- **Очень длинные пути (Windows 260 символов)**: ошибка при добавлении + рекомендация включить long paths; манифест приложения включает `longPathAware`
- **Vault через symlink на себя**: отслеживать `realPath` посещённых папок при сканировании, прерывать при цикле
- **Malformed/оборванный stream Claude**: считать ошибкой, rollback текущего файла
- **`git` возвращает stderr без non-zero exit code**: парсить stderr на паттерны "fatal:", "error:" дополнительно к exit code

### Обработка ошибок Claude API

- **Rate limit**: показывать таймер "Повторить через N секунд" (из заголовка `Retry-After`)
- **Timeout**: `CancellationTokenSource(TimeSpan.FromMinutes(5))` на каждый вызов SDK
- **Невалидный API key**: проверочный запрос при вводе; ошибка "Недействительный API key"

## [10] БЕЗОПАСНОСТЬ И ROBUSTNESS (аудит)

### Атомарные записи

**`index.md`, `log.md` при Ingest:**
- Сначала записывать во временный файл `index.md.tmp` рядом с оригиналом
- После успешной записи — `File.Move(tmp, target, overwrite: true)` (atomic на большинстве ОС)
- При rollback Ingest — удалять `.tmp` файл, оригинал остаётся нетронутым

**`settings.json`:**
- Запись атомарна: temp файл → fsync → rename replace
- При ошибке записи — старый `settings.json` сохраняется, показывать ошибку "Не удалось сохранить настройки"

**`ingest_state.json`:**
- Аналогично: temp → rename

---

### Поведение при переполнении IngestQueue

- Capacity = 100; при попытке добавить 101-й файл — `Channel.Writer.TryWrite` вернёт false
- UI показывает badge "Очередь: 100 / 100, ожидание..."
- Drag & drop не блокирует UI thread — запись в channel из background task
- Файлы не теряются: приложение ждёт освобождения слота (backpressure через `await writer.WriteAsync`)

---

### Восстановление после краша при разрешении конфликтов

- Состояние экрана конфликтов (какие файлы выбраны) сохраняется в `%APPDATA%/LLMWiki/conflict_resolution_state.json` после каждого выбора пользователя
- При старте: если `conflict_resolution_state.json` существует И `git status` показывает unmerged пути → автоматически открывать экран разрешения конфликтов с восстановленным состоянием
- После успешного завершения — удалять `conflict_resolution_state.json`

---

### Pull → Reindex → Crash

- После Pull приложение не откатывает git-состояние
- Частично успешный Ingest допустим — следующий инкрементальный Ingest корректно восстановит консистентность через `ingest_state.json`

---

### Замена raw-файла (Replace)

- При замене существующего raw-файла через диалог "Заменить" — существующие wiki-страницы с `source: <этот файл>` **обновляются агентом** при следующем Ingest, а не помечаются orphan

---

### Валидация путей (domain level)

Все пути через:
```csharp
// 1. Запрет пустых/whitespace
if (string.IsNullOrWhiteSpace(path)) throw new ArgumentException();

// 2. Нормализация и раскрытие symlinks
var resolved = Path.GetFullPath(path);

// 3. Проверка на invalid chars
Path.GetInvalidPathChars() // встроенная валидация

// 4. Path traversal guard — ОБЯЗАТЕЛЬНО для любой операции с файлами vault
if (!resolved.StartsWith(vaultRootRealPath, StringComparison.OrdinalIgnoreCase))
    throw new SecurityException("Path traversal attempt detected");
```

---

### Пустые и невалидные файлы

**Пустой `.md` файл (0 байт):**
- Допустим: `Title = filename`, `Content = ""`, граф без links

**Пустой ответ Claude (0 токенов, пустой stream):**
- Считается ошибкой операции Query/Ingest — rollback, показать ошибку

**Malformed YAML frontmatter:**
- Не роняет Ingest и граф
- Страница помечается warning-state (иконка в дереве файлов)
- Frontmatter игнорируется, страница обрабатывается как orphan без `source`

---

### Ограничения на размер wiki-файлов

- Максимальный размер одного wiki-файла, создаваемого Claude: **10 MB**
- Превышение обнаруживается через хук на `ToolUseBlock Write/Edit` — если итоговый размер файла > 10 MB → rollback текущего raw-file Ingest
- Граф при > 10 000 рёбер: отключать force simulation, переходить в simplified render mode (статичный layout)

---

### Ограничение длины чат-сессии

- Максимум **200 сообщений** или **2 MB** суммарного контекста в одной сессии
- При достижении лимита: показывать уведомление "Контекст сессии заполнен. Начать новый чат?" с кнопками "Да" / "Продолжить" (старые сообщения не сжимаются — просто показывать предупреждение)

---

### Безопасная аутентификация Git (PAT)

**Никогда не передавать PAT в URL командной строки** (`https://<pat>@github.com/...` — видно в process list, логах, crash dumps).

Вместо этого использовать **Git Credential Helper**:
```bash
# Перед push/pull:
git -c credential.helper='store --file=/tmp/llmwiki_git_cred' push

# Временный credential файл создаётся приложением в памяти,
# записывается во временный файл с правами 0600,
# удаляется сразу после операции
```

Или передавать через **environment variable** в изолированном `ProcessStartInfo.Environment`:
```csharp
var psi = new ProcessStartInfo("git") {
    UseShellExecute = false,
    Environment = {
        ["GIT_ASKPASS"] = pathToCredentialHelper, // мини-скрипт возвращающий PAT
        ["GIT_TERMINAL_PROMPT"] = "0"
    }
};
```

PAT никогда не появляется в `ArgumentList`, логах, или `settings.json`.

---

### Защита от command injection

**Все внешние процессы:**
```csharp
var psi = new ProcessStartInfo {
    FileName = "git",
    UseShellExecute = false,           // ОБЯЗАТЕЛЬНО
    RedirectStandardOutput = true,
    RedirectStandardError = true,
    // Аргументы ТОЛЬКО через ArgumentList, никогда string concatenation:
    ArgumentList = { "push", "--", remoteName }
};
```

**Валидация Git remote URL:**
- Допустимые форматы: `https://github.com/<user>/<repo>.git`, `https://github.com/<user>/<repo>`
- Запрещены: любые не-https схемы, embedded credentials (`user:pass@`), shell metacharacters (`;`, `|`, `&`, `` ` ``, `$`)
- Валидация через `Uri.TryCreate` + проверка `Host == "github.com"` и `Scheme == "https"`

---

### Защита от XSS в Markdown viewer

**Дополнительно к уже описанным sanitize правилам:**

- Запрещать в `href`/`src` атрибутах: `javascript:`, `data:`, `vbscript:`
- SVG не рендерить inline — отображать только как внешний image файл через `<img src="...">` с путём к файлу
- Внешние ссылки (`http://`, `https://`) открывать только после подтверждения пользователя: диалог "Открыть внешнюю ссылку в браузере?"
- `file://` ссылки в markdown — запрещать полностью

---

### Enforcement инструментов Claude (Authorization)

**Критично:** запрет через `CLAUDE.md` — это prompt-level защита, недостаточная против jailbreak.

Приложение должно enforce на уровне SDK:

```csharp
// CanUseTool callback блокирует Write/Edit вне wiki/ ДО filesystem write
options.CanUseTool = (toolName, toolInput) => {
    if (toolName is "Write" or "Edit") {
        var targetPath = ExtractPath(toolInput);
        var resolved = Path.GetFullPath(targetPath);
        var wikiPath = Path.Combine(vaultRoot, "wiki");

        if (!resolved.StartsWith(wikiPath, OrdinalIgnoreCase))
            return PermissionBehavior.Deny; // блокируем до записи
    }
    if (toolName == "Bash")
        return PermissionBehavior.Deny; // Bash запрещён всегда
    return PermissionBehavior.Allow;
};
```

Cleanup after-the-fact остаётся как второй эшелон защиты, но **не является основным механизмом**.

---

### Circuit breaker

После **5 последовательных сетевых ошибок** (Claude API или Git):
- Переходить в состояние `TemporaryUnavailable`
- Pause retries на **5 минут**
- Показывать в статус-баре: "Сервис временно недоступен. Повтор через N:SS"
- Ручная кнопка "Попробовать сейчас" сбрасывает circuit breaker

---

### Stalled stream

Если Claude stream не выдаёт токены **> 60 секунд**:
- Считать stalled stream
- Abort операции через `CancellationToken`
- Rollback, показать ошибку "Claude перестал отвечать"

---

### Race: Viewer vs Ingest rewrite

- Viewer открывает файл через `File.OpenRead` с `FileShare.ReadWrite` — читает snapshot на момент открытия
- При обнаружении изменения через `FileSystemWatcher` — показывает баннер "Файл изменился. Обновить?"
- Не блокирует Ingest от записи

---

### Race: Внешний git из терминала

- Перед каждой git-операцией выполнять `git status --porcelain` и сверять с ожидаемым состоянием
- Если обнаружены внешние изменения (неожиданные modified/untracked файлы) → показывать предупреждение "Репозиторий был изменён снаружи. Обновить состояние?"

---

### Дедупликация Ingest triggers

Все источники Ingest (drag&drop, autosync reindex, manual reindex, Pull callback) направляются через **единый централизованный `IngestScheduler`**:
- Если файл уже в очереди — не добавлять повторно (дедупликация по `RelativePath`)
- Если полная переиндексация уже запланирована — игнорировать инкрементальные добавления

---

### Кеш парсинга в рамках операции

В рамках одной операции (Ingest, Lint, граф rebuild):
- Использовать `Dictionary<string, ParsedDocument>` как in-memory кеш
- Не читать один и тот же файл дважды в рамках операции
- Кеш живёт только в рамках операции, не между операциями

---

### Стратегия тестирования (независимые тесты)

Для критических модулей обязательны **unit/integration тесты** (не только manual checklist):

| Модуль | Тип теста |
|---|---|
| Path validation + traversal guards | Unit + property-based (случайные пути) |
| Git auth (PAT через env, не URL) | Integration с mock git |
